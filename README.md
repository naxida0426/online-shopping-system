# 拾光商城

在线购物网站课程设计。后端使用 Node.js、Express 和 MySQL，页面由 EJS 渲染，搭配 Bootstrap 5、自定义 CSS 和少量原生 JavaScript。界面以中文为主，支持电脑和手机浏览。

## 已完成的功能

| 模块 | 功能 |
| --- | --- |
| 商品浏览 | 首页、分类、关键词搜索、分页、商品详情和快速预览 |
| 顾客账户 | 注册、用户名或邮箱登录、退出、账户页、MySQL 会话保存 |
| 购物车 | 添加、合并数量、修改、删除、库存检查、后端计算小计与合计 |
| 订单 | 收货信息、订单与明细快照、事务扣库存、重复提交防护 |
| 模拟支付 | 支付成功、取消本次支付、未支付订单取消与库存恢复 |
| 订单历史 | 本人订单查询、状态筛选、每页 10 笔分页、支付记录与详情 |
| 管理后台 | 商品新增、编辑、上下架、软删除；订单详情、发货和完成状态管理 |
| 销售统计 | 日期范围、新建订单数、已支付销售额、商品销量和 Chart.js 图表 |
| 确认邮件 | Nodemailer 邮件模块、MySQL 邮件任务、失败提示与限次重试 |

**全部支付均为课程模拟，不连接真实支付平台，不产生资金扣款。** 商品、购物车、订单、支付和统计数据均来自 MySQL；数据库故障时显示明确错误，不使用前端假数据代替。

邮件默认关闭。未配置 SMTP 时显示“尚未验证发送”，不会冒充已发送。公网部署尚未完成。

## 安装与运行

需要 Node.js 20+ 和 npm。数据库支持 MySQL 8.0.19+，推荐 8.4 LTS。

### Windows 首次运行

项目自带便携 MySQL 配置脚本，无需提前安装数据库。在项目目录执行：

```powershell
npm install
npm run mysql:setup
npm start
```

打开 [http://localhost:3000](http://localhost:3000)。也可以使用 `node app.js` 启动网站，Ctrl+C 停止网站。

`mysql:setup` 首次下载官方 MySQL 8.4.13 ZIP（约 268 MB），创建运行库和独立测试库、9 张表及示例商品，随机数据库密码与会话密钥写入本机 `.env`。数据库通常使用端口 3307，冲突时自动选择空闲端口。初始化提供 4 个分类、6 件有明确标记的示例商品，不创建默认网站账号。

重启电脑后执行 `npm run mysql:start`、`npm start`。结束开发时先停止网站，再运行 `npm run mysql:stop`。数据位于 `.local/mysql-data`，不要删除这个目录。`mysql:status` 检查端口，`db:check` 验证实际连接与表结构。

### 更新已有项目

先停止旧网站，再执行：

```powershell
npm install
npm run db:init
npm run db:check
npm start
```

这次新增了 Nodemailer、Chart.js 和 `order_emails` 邮件任务表，不能只刷新浏览器。`db:init` 可重复执行，不覆盖已有商品价格、库存或用户订单。已有表的字段变更仍需单独迁移，不能靠删库升级。

### 使用自己的 MySQL

仅在 `.env` 不存在时复制 `.env.example` 为 `.env`，填写 `DB_HOST`、`DB_PORT`、`DB_NAME`、`DB_USER` 和 `DB_PASSWORD`。运行账号只需项目库的读写权限；若初始化账号不同，另填 `DB_INIT_USER`、`DB_INIT_PASSWORD`。

执行 `npm install`、`npm run session:setup`、`npm run db:init`、`npm run db:check`、`node app.js`。详细说明见 [数据库配置](docs/database.md)。自装 MySQL 不需要执行便携环境命令。

`.env`、`.local`、`node_modules` 和数据库备份均不提交 Git。仓库没有公开的管理员或顾客密码。

## 顾客使用流程

1. 在 `/register` 创建顾客账号，通过 `/login` 登录。用户名支持中文、字母、数字和下划线；密码经 bcrypt 加密保存。
2. 在商品详情选择数量并添加到购物车，同款会累加，每种最多 999 件且不能超过库存。修改数量后点击“更新”，移除请点击“删除”。
3. 在 `/checkout` 核对整份购物车，填写虚构的收货人、11 位中国大陆手机号和详细地址，提交订单。
4. 后端重新读取商品状态、价格和库存。价格或清单变化时要求重新确认；成功后保存订单快照、扣库存并清空购物车，失败整单回滚。
5. 在订单详情进入“模拟支付”。“模拟支付成功”会保存支付记录；重复点击不会再次扣库存或重复创建支付单。
6. “取消本次模拟支付”仅结束这次支付，订单仍待支付且仍占用库存。若不再需要，请选择“取消订单”，确认后关闭订单并一次性恢复库存。
7. 从“我的账户 → 我的订单”按订单号、状态查询全部历史记录。订单详情、支付、取消与邮件重试均校验本人身份。

加入购物车不预留库存，提交订单时才扣减。订单金额、小计和统计使用 DECIMAL / 整数分计算，不接受浏览器提交的价格和总价。订单状态与支付状态独立：下单为“待确认 / 未支付”，模拟支付后为“已确认 / 已支付”，取消订单为“已取消 / 已取消”。

已支付订单暂不支持取消或退款。系统尚未自动关闭超时未支付订单，需要用户主动取消。实现与并发测试说明见 [订单与支付](docs/orders.md)。

## 创建管理员与使用后台

首次在本机 `.env` 填写 `BOOTSTRAP_ADMIN_USERNAME`、`BOOTSTRAP_ADMIN_EMAIL`、`BOOTSTRAP_ADMIN_PASSWORD`，用户名与邮箱不能和已有账号重复。密码至少 12 个字符，使用独立强密码，不要写入公开文档或聊天。

```powershell
npm run admin:create
```

通过普通登录页登录后，“我的账户”会显示“管理后台”入口，也可访问 `/admin`。脚本只创建首位管理员，已有有效管理员时不覆盖账号；创建后可从 `.env` 移除初始化密码。管理员与数据库初始化账号是不同概念。

- `/admin/products`：查询、新增和编辑商品。图片使用 `public/images` 中的本地文件，填写 `/images/文件名`；暂不支持上传或外部图片。
- 软删除需要单独确认，商品下架后不对顾客展示，旧订单快照保留。编辑页面检测库存与商品数据变化，防止旧表单覆盖最新库存。
- `/admin/orders`：查看收货信息和订单明细。仅已支付订单可按“已确认 → 已发货 → 已完成”推进，不能直接把未支付订单改成已支付。
- `/admin/stats`：按日期查询销售统计。新建订单数按创建日期计算；已支付订单数、收入、销量按模拟支付日期计算。取消和未支付订单不计收入。

所有后台路由在服务端验证角色，普通用户直接访问也会被拒绝。详细说明见 [后台与统计](docs/admin.md)。

## 配置订单确认邮件

默认 `MAIL_ENABLED=false`。在本机 `.env` 配置 `SMTP_HOST`、`SMTP_PORT`、`SMTP_SECURE`、`SMTP_USER`、`SMTP_PASSWORD`、`SMTP_FROM` 后，设置 `MAIL_ENABLED=true` 并重启网站。

```powershell
npm run mail:check
```

该命令只验证连接和认证，不代表收件箱已收到邮件。再使用有权管理的演示邮箱注册并支付一笔测试订单，检查收件箱、垃圾邮件和订单页状态。

邮件任务在模拟支付事务中落库，SMTP 发送在事务提交后执行。发送失败或未配置不会回滚订单及支付，也不会重复下单。可从本人订单页重试：间隔 60 秒、最多 5 次；重复支付不会重复发送已确认提交给 SMTP 的邮件。

**当前仅验证了本地邮件生成、失败处理和重试逻辑，尚未验证实际 SMTP 投递。** 配置、状态与重试限制见 [邮件说明](docs/mail.md)。

## 目录说明

```text
app.js                 应用入口、静态资源与错误处理
config/                环境变量、连接池、会话和共用事务锁
routes/                账户、商品、购物车、订单与后台路由
services/              业务查询、下单、支付、后台及邮件逻辑
middleware/auth.js     登录和管理员权限验证
utils/                 参数、金额、结算摘要与表单校验
views/                 EJS 页面，partials/ 为公共组件
public/                CSS、原生 JavaScript 与本地图片
sql/init.sql           9 张表及示例商品
scripts/               数据库、管理员及 SMTP 配置检查命令
tests/                 单元校验、HTTP 与真实 MySQL 集成测试
docs/                  数据库、购物车、订单、后台和邮件说明
```

## 测试与课堂验收

```powershell
npm run db:check
npm test
```

配置 `DB_TEST_NAME` 后，测试在独立 MySQL 库中运行，库名必须以 `_test` 结尾且不同于运行库。便携安装已准备测试库；未配置时相关用例会标记为跳过。自动测试强制关闭外部邮件发送，只清理本轮测试记录。

建议课堂按以下顺序演示：

1. 商品搜索、分类组合筛选、详情返回；注册、错误密码、正确登录和退出。
2. 添加同款商品、修改数量、删除；重新登录检查购物车保留，切换账号检查清单隔离。
3. 提交订单并查看库存；重复提交原表单只能得到同一订单。用另一账号访问订单应返回 404。
4. 模拟支付成功、取消本次支付后重试、取消另一笔未支付订单；检查支付记录与库存变化。
5. 用普通账号访问后台确认被拒绝；用管理员新增、编辑、上下架和软删除商品。
6. 将已支付订单依次标记发货、完成；检查未支付订单无法发货。
7. 在统计页选择日期，对照订单金额与图表下的数据表。自动测试还会核对收入排除未支付和取消订单。
8. 未配置 SMTP 时检查“尚未验证发送”；配置后再实际确认收件箱。使用手机模式检查关键页面。

自动测试还覆盖事务中途失败回滚、最后一件商品并发下单、支付和取消同时提交、邮件失败重试、历史分页、管理员权限撤销及跨进程数据持久化。

后续工作集中在整体联调、安全复查、部署与课程报告。当前尚无公网地址；真实支付、退款、自动超时关闭、邮箱验证和密码找回不在已完成范围内。
