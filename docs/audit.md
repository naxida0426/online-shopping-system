# 系统检查与验收记录

检查日期：2026-11-01。范围为当前 Express + EJS + MySQL 项目，在原有结构上修复问题，不改动数据库表结构。

## 本轮修复

1. 注册邮箱原校验只检查 `@` 和点号，会接受显示名、控制字符及异常域名。现在注册和 SMTP 发件地址共用普通邮箱校验，保留加号标签、子域名等正常格式。历史账号若保存了异常地址，发信前也会被拒绝，订单及支付状态保留。
2. 不支持的请求字符集、压缩方式原先会被当作 500。现在返回 415；不完整或解析失败请求返回 400；超长表单或参数过多仍返回 413。响应不回显原始输入。

两处问题均先由新增测试复现，再修复。新测试还覆盖关键 EJS 页面在三种身份及空结果下的渲染、后台写操作权限、数据库异常消息隔离、历史异常收件地址拦截。

## 复查方法

```powershell
npm run db:check
npm test
npm audit --omit=dev
git check-ignore .env
git ls-files .env
git diff --check
```

便携环境已配置独立测试库；自装 MySQL 需先配置不同于运行库的 `DB_TEST_NAME`。`npm test` 中数据库用例若显示 skipped，不能据此声称交易和权限测试通过。测试强制关闭外部发信，并仅清理本轮测试记录。

人工演示使用 README 的两名顾客与管理员，依次核对搜索、登录、购物车、下单、模拟支付、取消、越权、商品维护、发货和销售额；真实邮件需检查收件箱。重启 Node.js 后确认购物车及订单仍在。
