# 购物车说明

购物车在现有的 `cart_items` 表中保存，每位用户与每件商品的组合唯一。页面由 EJS 服务端渲染，增改删使用普通表单提交，不依赖前端保存商品数据。

## 路由与处理方式

| 方法与地址 | 作用 | 主要字段 |
| --- | --- | --- |
| `GET /cart` | 查看当前用户购物车 | 无 |
| `POST /cart/items` | 添加商品，已有条目累加数量 | `productId`、`quantity`、`_csrf` |
| `POST /cart/items/:id/quantity` | 将条目修改为指定数量 | `quantity`、`_csrf` |
| `POST /cart/items/:id/delete` | 删除条目 | `_csrf` |

这里的 `:id` 是购物车条目 ID，不是商品 ID。所有查询和写入都使用登录会话中的用户 ID 作为归属条件，忽略表单中的 `userId`。修改和删除他人的条目与条目不存在一样返回 404。

未登录访问会跳转登录页，登录后返回购物车。商品详情的游客入口则会在登录后返回原来的商品详情，需要用户再次选择数量并添加，不自动重放未登录的请求。

成功操作后返回 303 并跳转购物车，成功提示只显示一次，刷新页面不会重复提交。数量格式错误返回 422，库存或状态冲突返回 409，表单校验失败返回 403。数据库异常由公共错误处理返回 503，不显示 SQL、凭据或原始驱动错误。

## 数量、金额与库存

- 数量只接受 1–999 的正整数，拒绝零、负数、小数、指数写法、数组和空值。不能通过改 URL 绕过归属或数量检查。
- 添加与更新会重新读取商品上架状态、软删除标记、分类状态和库存。重复添加时检查的是合并后的数量。
- 增改删与结算共用用户行事务锁，同一用户的操作依次完成。增改时对商品加排他锁、分类加共享锁，再处理购物车条目，防止并发累加丢失或超过库存。实现依据 [MySQL 锁定读说明](https://dev.mysql.com/doc/refman/8.4/en/innodb-locking-reads.html)。
- 购物车不扣库存，也不预留库存。不同账号可以各自保存同一商品；提交订单时再核对整份购物车并扣减库存。
- 价格读取 `products.price`，不读取客户端单价或小计。后端将 DECIMAL 字符串转为 BigInt 整数分后乘数量并累加，最后格式化为两位小数字符串。
- 商品状态或库存变化后，失效条目仍保留在清单中并说明原因，但不计入合计。库存仍大于零时可减量恢复；失效条目也允许删除。

## 如何验证

执行 `npm test`。真实 MySQL 用例在独立测试库创建两位用户和专用商品，验证重复添加、更新、删除、价格篡改、跨账号操作、CSRF、无效输入、缺货、下架、软删除和分类停用。

并发测试向同一条库存为 2 的商品同时发起 4 次添加，断言只有两次成功、购物车只有一条记录且数量为 2，商品库存仍为 2。持久化测试会退出后重新登录，并启动另一个 Node.js 进程读取同一购物车。

测试结束会清理本轮生成的用户、商品、购物车条目与会话。课堂演示可按 README 的流程操作，使用独立演示账号，不需要公开密码。

购物车目前按整份清单结算，不包含部分勾选、优惠券或运费。有失效商品时先调整清单，全部有效后可进入确认订单页。下单逻辑重新查询价格和库存，不直接使用购物车页曾经展示的合计，详见 [订单说明](orders.md)。
