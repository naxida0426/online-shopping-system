# 闪购与兑换码

首页按上海时区开启当日闪购，从在售、有库存商品中随机选一件展示；每次从八折抢购入口成功加入购物袋后，会自动随机切换为另一件不同商品。当前展示由数据库共享，其他访客的旧抢购入口会校验商品是否仍为当前活动。卡片只展示名称、原价、八折价、倒计时和抢购入口，不展示图片。

从闪购入口加入购物袋的商品按八折结算；普通商品入口保持原价。同款在购物车中合并数量，已经享受活动的行继续按活动价计算。活动于上海时间次日零点结束，过期后的购物车恢复原价，过期前的结算表单会要求重新核对；已经创建的订单使用下单时的价格快照。展示商品轮换不影响已入购物袋商品在当日截止前的八折资格。

兑换码由后端生成并绑定当前账户，每天一张，面值为随机整数 ¥50–100，24 小时内可应用于本人未支付订单。每单限用一张，可以与闪购叠加，实际抵扣不超过商品金额。

在待支付订单详情页或支付页面输入兑换码并点击“抵扣金额”，后端会锁定订单与兑换码，更新订单实际应付及已有未成功支付记录。重复应用同一码不会重复抵扣。成功支付时核销；取消本次支付保留占用，取消订单或订单超时则释放尚未核销的兑换码。过期兑换码不可重新应用。

订单回执、支付记录、订单列表、销售总额和 SMTP 确认邮件均使用优惠后的实付金额；后台商品金额列为兑换码抵扣前的商品明细金额。商品原价、闪购已优惠和兑换码实际抵扣在回执中分别列出，历史订单保持原状。

## 数据库部署

已有数据库运行一次：

```powershell
node scripts/migrate-promotions.js
```

脚本使用已有初始化数据库凭据，幂等创建 `flash_offers`、`promotion_codes`、`order_promotions` 并补充购物车活动字段。新环境 `npm run db:init` 自动执行此升级。运行检查会验证全部 15 张业务表及活动字段。

新入口：`POST /promotions/codes`（领取兑换码）和 `POST /orders/:id/coupon`（应用抵扣），均要求登录及 CSRF 校验。原购物车、结算、支付路径保持不变。金额全部采用整数分计算。

## 验证

自动测试覆盖：八折舍入、面值范围、账户归属、CSRF、并发领取及兑换、重复支付、事务失败回滚、过期拒绝、取消释放、零元订单、SMTP 内容和支付记录金额一致。浏览器验证登录抽码 → 闪购加购 → 下单 → 支付页抵扣 → 模拟支付成功，并检查手机端布局。测试仅使用独立数据库，不向外部邮箱发信。

首页左侧主推商品也从全部在售、有库存商品中随机选择，每次加载首页重新抽取，不受当前列表分页和分类筛选限制。闪购成功后页面通过 `GET /promotions/flash` 更新卡片与倒计时，不刷新整个页面。本次轮换功能沿用原有促销表结构，无新增数据库迁移。
