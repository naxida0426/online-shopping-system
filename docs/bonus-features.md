# 加分功能：订单超时关闭与收货地址簿

## 升级与启动

停止旧网站，保留现有 `.env` 与 `.local/mysql-data`，执行：

```powershell
npm run db:init
npm run db:check
npm start
```

`db:init` 新增 `addresses` 表，补齐 `orders.expires_at`、`orders.cancel_reason` 及超时查询索引。升级账号须有 CREATE / ALTER / UPDATE 权限。升级可重复执行，不删除旧数据；旧待支付订单按创建时间加 30 分钟补齐截止时间，已有截止时间不变。启动后会补关已经超时的订单并恢复预留库存。

## 订单超时自动关闭

- 新订单默认保留 1800 秒。可在本机 `.env` 设置 `ORDER_PAYMENT_TIMEOUT_SECONDS=60` 进行一分钟演示，范围 1–86400；修改后重启，仅影响新订单，不改变旧订单的期限。
- 订单详情和模拟支付页显示剩余时间与支付截止时间。倒计时到零后禁用当前支付按钮，并提供刷新订单状态的链接。关闭判断由数据库时间决定，前端不能延长期限。
- 网站启动时立即扫描，之后每 15 秒扫描一批，每批最多 100 笔；逐单事务关闭，单笔故障会回滚并在下轮重试。服务停止时任务暂停，重启后补关。多个进程扫描同一订单也只回补一次库存。
- 查看本人订单列表/详情时会检查到期订单；提交模拟支付或主动取消时，在事务取得锁后再次检查截止时间。到期时直接关闭并提交事务，不能继续支付，取消一次支付也不会延长截止时间。
- 自动关闭保留现有状态枚举，订单和支付状态均为 `cancelled`；`cancel_reason=timeout` 表示超时，`customer` 表示主动取消。后台订单详情展示原因。
- 用户行、订单、支付记录、商品按一致顺序加锁。恢复库存、保存取消支付记录与关闭订单在同一事务完成。已支付订单不受超时任务影响；停用账号的待支付订单仍会正常释放库存。

演示：创建订单，查看倒计时，保留支付表单等待超时；刷新订单应显示自动关闭，提交旧支付表单也不能付款，商品库存恢复至下单前。再用另一笔截止前已支付订单核对它不会被超时任务关闭。

## 收货地址簿

入口：我的账户 → 收货地址簿（`/account/addresses`）。

- 支持新增、编辑、删除、设置默认，最多 20 个地址；第一个地址自动默认。
- 同一账号的写入沿用用户行锁，防止并发新增超出上限、并发设置产生多个默认地址。默认地址通过另一个地址的“设为默认”按钮切换。
- 删除前单独展示确认页；删除默认地址时，最新添加的剩余地址自动成为默认。删光后结算改为手动填写。
- 结算自动填入默认地址，选择其他地址立即更新表单。可以临时修改收货信息，不回写地址簿；没有 JavaScript 时仍可通过地址链接选择，或直接填写表单。
- 提交订单使用本次填写的收货信息，复制到订单快照。地址簿的后续编辑、删除不会改变历史订单。
- 所有地址查询与写入均绑定登录用户，其他账号访问返回 404；写操作校验 CSRF。收货人、手机号、地址沿用现有后端校验，页面转义用户输入；地址信息不写入会话，页面禁止缓存。

演示：保存两个地址，切换默认后进入结算，选择另一地址并临时改名下单；再编辑或删除地址簿记录，订单详情的原收货信息保持不变。

## 验证

`npm test` 在独立测试库执行原有流程及新增用例。新增覆盖地址权限、CSRF、校验、默认切换、并发上限、结算错误回显、订单快照、期限保存、旧订单升级、过期表单、支付/取消/关闭并发、事务回滚、后台补关及停用账号库存释放；不向外部邮箱发信。
