# 订单确认邮件

使用 Nodemailer，通过环境变量配置 SMTP。当前仓库只验证了本地消息生成、数据库任务与失败重试；**实际 SMTP 发送及收件箱投递尚未验证**。

## 配置与验证

1. 在服务商处开通 SMTP，取得有权使用的账号与授权码，不要把授权码当作普通网站登录密码公开。
2. 在本机 `.env` 填写 `SMTP_HOST`、`SMTP_PORT`、`SMTP_SECURE`、`SMTP_USER`、`SMTP_PASSWORD`、`SMTP_FROM`。
3. 通常 465 使用 `SMTP_SECURE=true`；587 使用 `false` 并要求 STARTTLS。代码保持证书校验，不提供跳过 TLS 的选项。
4. 设置 `MAIL_ENABLED=true`，重启网站，执行 `npm run mail:check`。该命令只验证连接及认证。
5. 用有权管理的演示邮箱创建网站账号，并完成一笔模拟支付，检查订单页和收件箱。SMTP 接受邮件也可能因收件方策略进入垃圾邮件或退信，不能据此宣称收件人已收到。

默认关闭时不连接 SMTP，订单页明确显示“SMTP 未配置，尚未验证发送”。测试框架强制关闭外部发送，Nodemailer JSON transport 只用于验证邮件内容，不能当作真实投递成功。

## 任务与失败处理

支付事务中插入 `order_emails`，每个订单至多一条确认邮件任务。事务提交后再尝试 SMTP，因此网络错误不会回滚已支付订单或重复扣库存。

任务状态为 `pending`、`sending`、`sent`、`failed` 或 `skipped`。`sent` 只表示 SMTP 已接受目标收件人，实际送达以收件箱为准。错误只记录简短代码，不记录 SMTP 密码、原始响应或收货信息。邮件正文包含订单号、模拟金额和商品明细，不包含完整收货地址。

本人已支付订单可在详情中重试，间隔 60 秒、最多 5 次。数据库条件更新抢占任务，防止并发重复发送；已发送任务不再发送。进程异常留下的 `sending` 任务在 5 分钟后允许重试，没有常驻定时发送进程。

SMTP 与数据库无法共享事务。若 SMTP 已接受后进程在标记 `sent` 前中断，后续重试仍可能重复投递；固定 Message-ID 可辅助识别，但不能保证外部系统绝对只收一封。需要严格投递语义时应扩展专用邮件队列和回执处理。

邮箱所有权验证、退信接收、自动重试及批量发送尚未实现。不要使用真实个人资料进行课程演示。
