# 管理后台与销售统计

后台统一使用普通登录系统和 `requireAdmin` 中间件。角色每次从 MySQL 重新读取；撤销管理员角色后，旧会话也不能继续进入后台。写入事务会再次检查角色，表单操作还需通过 CSRF 校验。

## 管理员初始化

在本机 `.env` 填写 `BOOTSTRAP_ADMIN_USERNAME`、`BOOTSTRAP_ADMIN_EMAIL`、`BOOTSTRAP_ADMIN_PASSWORD`，执行 `npm run admin:create`。密码采用 bcrypt、工作因子 12，不输出明文。脚本使用数据库命名锁防止并发初始化；存在有效管理员时不再创建或覆盖。

管理员用户名和邮箱必须尚未注册。仓库不内置默认密码，也不提供公开提权接口；需要新增管理员时应由数据库维护者受控操作。创建后删除 `.env` 中的初始化密码不影响网站登录。

## 商品管理

新增与编辑字段包括 SKU、名称、分类、描述、价格、库存、图片地址、状态、标签、背景色和示例标记。SKU 唯一，金额最多 8 位整数和 2 位小数，库存为非负整数。图片只允许 `/images/` 下已存在的本地图片，不抓取外部 URL，不提供上传接口。

编辑页面携带商品字段摘要。保存时锁定商品行并比较摘要，若期间有下单、取消或其他编辑改变了库存/商品信息，旧表单返回 409 并重新加载数据，避免覆盖最新库存。输入不合格返回 422，重复 SKU 返回 409。

上架商品仍需分类启用才会对顾客可见。软删除通过单独确认页完成，仅修改状态与删除时间，不物理删除数据，因此旧订单和外键关系保留。已软删除商品不直接恢复或编辑。

## 订单管理

管理员可分页、筛选全部订单并查看必要的收货信息。仅允许已支付订单按 `confirmed → shipped → completed` 推进；禁止跳级、倒退或将未支付订单伪装为已支付。重复提交相同目标状态不会再更新记录。状态修改沿用 `updated_at` 时间字段。

取消未支付订单由顾客流程处理；已支付订单不支持取消或退款。后台不提供手工修改支付金额、支付状态或删除订单的表单。

## 统计口径

- 新建订单数：按 `orders.created_at` 落在所选日期范围内计数，包含未支付和已取消记录。
- 已支付订单数、销售额：按 `paid_at` 范围，要求 `payment_status=paid` 且订单未取消。
- 商品销量与收入：同一支付口径，累计订单明细的数量与下单时小计，不按商品现价重算。
- 结束日期全天包含在范围内；最多查询 366 天。未支付或取消订单不计收入。当前所有收入均为课程模拟金额。

统计在一致的数据库读事务中完成，订单金额汇总与商品明细汇总分开，避免一单多件商品导致订单总额被重复相加。商品软删除后仍保留历史收入与销量。Chart.js 从本地依赖加载，数据来自后端 SQL 聚合；页面同时显示对应数据表，空区间显示零值。

自动测试使用独立库中的付费、未付费及取消订单核对销售额、销量、日期边界、权限和状态转换，不向运行库添加统计假数据。
